# 客观评标规则执行设计

## 目标与范围

本阶段在已有 `11_evaluation_rules.json` 基础上执行客观评分规则，生成独立的客观评分产出物。只处理 `evaluation_type = objective` 的评分项，不处理主观评分、否决规则、总分汇总、排名或中标候选人判断。

本阶段的核心原则是：规则由招标文件产物提供，事实优先复用现有投标文件解析和专项检查产物，程序执行确定性计算；无法可靠确认的事实不猜测分数，也不把“未找到”自动解释为 0 分。

## 架构接入

新增客观评分执行模块，负责以下步骤：

1. 校验并读取 `11_evaluation_rules.json`。
2. 按稳定顺序筛选客观评分项，排除主观评分项和否决规则。
3. 通过投标文件真实路径解析已有 `structured_document.json` 及同目录的合规检查产出物；校验文件哈希，避免评标任务和合规任务目录不同导致错用证据。
4. 复用 `08_template_text_reviews.json`、`09_attachment_reviews.json`、`10_file_requirement_reviews.json`、`10_performance_reviews.json` 和投标文件结构化解析结果。
5. 针对当前已识别的 8 个客观评分项执行明确的证据判断和确定性计算；未知规则进入 `unsupported`，不静默丢失。
6. 通过现有 `ComplianceExtractionRecorder` 写入独立 `objective_scores.json`。

评标工作流在评标规则提取完成后执行客观评分。评标规则缓存命中时也必须执行客观评分，不能因为规则提取被缓存而跳过本阶段。若存在可复用的投标文件解析产物则直接使用；只有产物不存在时才调用现有投标文件解析器一次，不新增独立解析流程。

## 客观评分项执行策略

### 技术标准和要求的偏离情况

只有当前投标文件范围中存在技术标及已完成的技术要求响应事实，才能按偏离数量计算。当前只有商务投标文件或没有技术响应检查结果时，状态为 `file_scope_missing` 或 `evidence_insufficient`，不按“全部满足”给分。

### 项目经理资质

必须同时核验招标规则要求的学历、专业、工作年限、项目管理经验、项目管理能力证明、身份证、学历或证书、简历、近三个月任一月份社保及缴费单位等条件。任何一项无法确认时，状态为 `evidence_insufficient`；不能只依据 PMP 或单一证书给满分。

### 团队成员情况

人数取满足身份证、规定月份社保和缴费单位为投标人的证明要求的有效人员数，不取名单行数。只有有效人数及档位事实完整时才使用招标文件的分档公式计算；无法确认有效人数时为 `evidence_insufficient`。

### 类似案例 1

使用既有业绩合同检查结果和业绩表标记，区分资格要求业绩与评分业绩。只允许在资格业绩已可靠识别且被排除、评分业绩同时满足时间、同类型、合同及证明材料要求时，按“每增加一项 1 分、最高 5 分”计算。任何资格业绩排除关系或有效性无法可靠确认时为 `evidence_insufficient`。

### 类似案例 2

在类似案例 1 的业绩有效性和资格业绩识别基础上，计算评分业绩合同累计金额，并明确剔除资格要求业绩金额。不能把全部合同金额直接相加；资格业绩金额或合同金额无法可靠确认时为 `evidence_insufficient`。

### 人员稳定性承诺

必须找到并核验对应承诺及其适用事实，按招标文件的比例档位确定性计算。当前文件范围不包含该承诺时为 `file_scope_missing`；不能以人员名单或其他普通承诺替代。

### 中国电信供应商不良行为处理结果执行

该规则依赖外部供应商系统或评标现场数据。当前没有可靠外部事实时为 `external_data_required`，不因满分为 0 而伪造一个已执行的分数。

### 报价评分

必须具备所有有效投标人的经评审评标价、有效投标人数 `n` 和基准价 `P0`。单个投标文件不能模拟其他投标人或基准价，状态为 `other_bidder_data_required`。

## 产出物结构

`objective_scores.json` 至少包含：

- 基础信息：规则产出物、投标文件、实际复用产出物、规则项数量、是否重复解析、LLM 调用统计。
- `score_items`：每个客观评分项一条记录。
- 每条记录包含评分项名称、评分大类及父级、满分、原始规则、执行状态、实际得分（可计算时）、使用事实、计算过程、证据来源、关联产出物、无法评分原因和招标规则来源 block。
- 统计信息：各状态数量、已自动评分数量、可确定得分合计；本阶段明确不计算最终总评标得分。

建议状态值：

- `auto_scored`
- `evidence_insufficient`
- `file_scope_missing`
- `other_bidder_data_required`
- `external_data_required`
- `unsupported`

所有评分项均按规则中的稳定顺序写入，证据和关联产出物路径也按稳定顺序写入，避免输出受文件遍历顺序影响。

## LLM 与性能

当前真实投标文件已有结构化解析和业绩检查产物，客观评分阶段不新增 LLM 调用。若未来确实需要补充取证，应明确记录调用原因、输入输出 token、耗时和重试信息，并优先限定在缺失的投标文件区域；本阶段不重新检查整份投标文件。

## 测试与验收

先用单元测试覆盖规则筛选、状态判定、资格业绩排除、人数分档、证据不足不等于 0 分、价格数据不足和来源追溯，再接入工作流测试产出物写入。最后使用当前真实招标文件和投标文件运行一次，核验 8 个客观评分项、状态与原因、业绩排除、项目经理全条件、团队有效人数、技术标范围、单投标人报价及没有重复解析。
